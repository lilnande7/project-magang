## BAB II LANDASAN TEORI

### 2.1 IT Support
IT Support adalah kegiatan bantuan teknis yang bertujuan memastikan perangkat keras, perangkat lunak, dan layanan teknologi informasi dapat digunakan dengan baik oleh pengguna. Dalam lingkungan instansi, IT Support dapat mencakup perbaikan printer, update driver, instalasi aplikasi, pengecekan jaringan, dan penyelesaian gangguan umum pada komputer.

Pada pelaksanaan magang ini, saya beberapa kali membantu permasalahan umum seperti printer yang tidak terdeteksi oleh PC, pembaruan driver, dan troubleshooting sederhana pada perangkat kerja.

### 2.2 Web Company Profile
Web company profile adalah website yang menampilkan profil instansi, visi dan misi, layanan, struktur organisasi, informasi kontak, serta konten pendukung lain yang bertujuan memperkenalkan lembaga kepada publik. Website jenis ini juga berfungsi sebagai media informasi resmi dan sarana meningkatkan kredibilitas instansi.

Pada proyek ini, website company profile digunakan untuk mendukung kebutuhan akreditasi perpustakaan serta menampilkan informasi yang lebih tertata dan mudah diakses.

### 2.3 Laravel
Laravel adalah framework PHP yang digunakan untuk membangun aplikasi web dengan struktur yang rapi, aman, dan mudah dikembangkan. Laravel menyediakan fitur routing, controller, model, migration, validation, middleware, autentikasi, dan blade template.

Dalam proyek ini, Laravel digunakan sebagai kerangka utama pengembangan website karena memudahkan pengelolaan data, pemisahan logika aplikasi, dan pembuatan panel admin.

### 2.4 PHP
PHP adalah bahasa pemrograman server-side yang umum digunakan dalam pengembangan web dinamis. PHP berperan dalam pengolahan data pada server, validasi input, koneksi ke database, dan pembuatan halaman yang bersifat interaktif.

### 2.5 SLiMS 9
SLiMS 9 (Senayan Library Management System) adalah aplikasi manajemen perpustakaan berbasis web yang digunakan untuk mengelola koleksi, anggota, sirkulasi, dan data pustaka lainnya. SLiMS sangat membantu perpustakaan dalam proses input data koleksi referensi dan arsip digital.

Selama magang, saya bertugas melakukan scanning foto serta memasukkan buku referensi, jurnal, dan tugas akhir taruna ke dalam SLiMS 9 agar data perpustakaan lebih tertata dan mudah dicari.

### 2.6 Docker
Docker adalah platform containerisasi yang digunakan untuk menjalankan aplikasi dan lingkungan pendukungnya secara terisolasi. Docker memudahkan proses instalasi, deployment, dan konsistensi lingkungan kerja antara satu perangkat dengan perangkat lain.

Pada proyek ini, Docker digunakan untuk membantu menyiapkan lingkungan Laravel, PHP, dan database agar proses pengembangan lebih stabil.

### 2.7 Visual Studio Code
Visual Studio Code adalah text editor dan IDE ringan yang digunakan untuk menulis, mengelola, dan men-debug kode program. VS Code mendukung banyak ekstensi yang membantu pengembangan web, termasuk Git, PHP, dan format kode.

### 2.8 GitHub
GitHub adalah platform pengelolaan repositori kode berbasis Git yang digunakan untuk version control, kolaborasi, dan penyimpanan kode proyek. Dengan GitHub, perubahan kode dapat ditelusuri dan dikelola secara lebih aman.

### 2.9 Ubuntu dan Windows
Ubuntu adalah sistem operasi berbasis Linux yang umum digunakan untuk kebutuhan server dan pengembangan web, sedangkan Windows banyak digunakan untuk aktivitas kerja harian dan kompatibilitas perangkat. Penggunaan kedua sistem operasi ini membantu menyesuaikan kebutuhan pengembangan dan operasional di instansi.

### 2.10 Struktur Database, Model, dan Controller
Dalam framework Laravel, migration digunakan untuk membangun struktur tabel database, model digunakan untuk mewakili tabel dan relasinya, sedangkan controller berfungsi sebagai penghubung antara request dari pengguna dengan proses pengolahan data.

### 2.11 Admin Dashboard
Admin dashboard adalah panel pengelolaan yang hanya dapat diakses oleh pengguna dengan hak tertentu. Fitur ini digunakan untuk mengelola data buku, berita, pengguna, pengaduan, serta statistik sistem.

Hasil dari tahap ini adalah aplikasi dapat dijalankan dengan konfigurasi yang lebih terstruktur, baik pada perangkat berbasis Linux maupun Windows.

### 4.4 Perancangan Sistem
Perancangan sistem dilakukan untuk menentukan kebutuhan halaman, alur data, dan pengelolaan konten. Website company profile dirancang agar menampilkan informasi profil, visi dan misi, berita, galeri, layanan kontak, serta akses ke halaman admin.

Struktur sistem yang dibangun mencakup:
1. Halaman publik untuk pengunjung umum.
2. Panel admin untuk pengelolaan konten.
3. Basis data untuk menyimpan informasi buku, kategori, berita, pengaduan, log pengunjung, dan relasi pengguna.
4. Chatbot untuk membantu pertanyaan terkait koleksi perpustakaan.

### 4.5 Struktur Database: Migration dan Fungsinya
Berikut adalah migration utama yang digunakan pada proyek ini beserta fungsinya:

| Migration | Fungsi |
| --- | --- |
| `create_users_table` | Menyimpan data akun pengguna sistem. |
| `add_avatar_path_to_users_table` | Menambahkan kolom avatar pada data user. |
| `create_roles_table` | Menyimpan data peran pengguna seperti admin dan super-admin. |
| `create_permissions_table` | Menyimpan daftar hak akses sistem. |
| `create_user_roles_table` | Menghubungkan user dengan role yang dimiliki. |
| `create_role_permissions_table` | Menghubungkan role dengan permission. |
| `create_books_table` | Menyimpan data koleksi buku perpustakaan. |
| `create_categories_table` | Menyimpan kategori buku. |
| `create_borrowings_table` | Menyimpan data peminjaman buku. |
| `create_news_table` | Menyimpan berita dan informasi publik. |
| `create_complaints_table` | Menyimpan data pengaduan atau pesan dari pengguna. |
| `create_visitor_logs_table` | Menyimpan log kunjungan website. |
| `create_user_activity_logs_table` | Menyimpan aktivitas pengguna/admin pada sistem. |
| `create_posts_table` | Menjadi dasar penyimpanan konten posting tambahan. |
| `create_pengumumen_table` | Menyimpan data pengumuman internal. |

### 4.6 Model yang Digunakan dan Fungsinya
Model yang digunakan dalam pengembangan proyek ini antara lain:

| Model | Fungsi |
| --- | --- |
| `User` | Mewakili data pengguna sistem dan relasinya dengan role. |
| `Role` | Mewakili peran pengguna seperti admin atau super-admin. |
| `Permission` | Mewakili hak akses yang dapat diberikan ke role. |
| `Book` | Mewakili data buku, kategori, stok, status, dan relasi peminjaman. |
| `Category` | Mewakili kategori koleksi buku. |
| `Borrowing` | Mewakili transaksi peminjaman dan pengembalian buku. |
| `News` | Mewakili berita, slug, status publikasi, dan data penulis. |
| `Complaint` | Mewakili pengaduan yang masuk dari pengguna. |
| `VisitorLog` | Mewakili log pengunjung website. |
| `UserActivityLog` | Mewakili aktivitas admin atau pengguna pada sistem. |

Relasi antar model membantu sistem mengelola data secara terstruktur. Contohnya, satu buku dapat memiliki kategori, satu buku juga dapat memiliki banyak peminjaman, dan berita memiliki penulis yang berasal dari model user.

### 4.7 Controller yang Digunakan dan Kegunaannya
Controller berfungsi sebagai pengendali alur aplikasi. Controller utama yang digunakan pada proyek ini adalah:

| Controller | Kegunaan |
| --- | --- |
| `HomeController` | Menampilkan halaman utama, daftar berita, dan detail berita. |
| `DashboardController` | Menampilkan statistik admin, data terbaru, grafik, dan export pengunjung. |
| `Admin\BookController` | Mengelola data buku melalui fitur CRUD. |
| `Admin\NewsController` | Mengelola berita, termasuk publish, edit, dan hapus. |
| `ContactController` | Menangani halaman dan pengiriman pesan hubungi kami. |
| `Auth\LoginController` | Mengelola proses login dan logout pengguna. |
| `Auth\RegisterController` | Mengelola registrasi pengguna baru. |
| `API\ChatbotController` | Menangani chat asisten perpustakaan berbasis dataset dan Gemini API. |

### 4.8 Penjelasan Dashboard dan Panel Admin
Dashboard admin digunakan sebagai pusat kontrol untuk memantau dan mengelola data. Dari hasil implementasi pada proyek ini, dashboard menampilkan statistik seperti jumlah buku, kategori, pengguna, peminjaman aktif, berita, dan log aktivitas.

Panel admin memiliki akses terbatas berdasarkan middleware auth dan role. Hal ini penting agar hanya admin atau super-admin yang dapat mengelola data inti. Pada halaman admin, tersedia menu untuk mengelola buku, berita, pengguna, dan pengaduan.

### 4.9 Penjelasan Route Web
Route web menjadi penghubung antara URL dan controller atau view yang dituju. Berdasarkan implementasi pada proyek ini, route utama meliputi:
1. `/` untuk halaman beranda.
2. `/berita` untuk daftar berita.
3. `/news/{id}` untuk detail berita.
4. `/profile` untuk profil perpustakaan.
5. `/hubungikami` untuk form dan informasi kontak.
6. `/galeri0` untuk halaman galeri.
7. `/opac` dan `/opac/detail/{id}` untuk halaman katalog.
8. `/login`, `/register`, dan `/logout` untuk autentikasi.
9. `/admin/*` untuk panel admin.

Route admin dilindungi middleware `auth` dan `role:super-admin|admin`, sehingga keamanan data lebih terjaga.

### 4.10 Penjelasan Chatbot
Chatbot pada proyek ini digunakan sebagai asisten perpustakaan digital. Fungsinya adalah membantu pengguna mencari informasi koleksi dengan cepat. Chatbot memeriksa data koleksi terlebih dahulu dari dataset senayan, lalu jika data belum cukup, sistem dapat meneruskan pertanyaan ke Gemini API.

Chatbot dibuat agar dapat menjawab pertanyaan secara sopan, ringkas, dan relevan, khususnya yang berkaitan dengan buku, kategori, lokasi, stok, dan status koleksi. Jika data tidak mencukupi, chatbot menyarankan pengguna untuk menghubungi pustakawan atau mencari di katalog.
